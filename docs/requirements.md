# سند تحلیل نیازمندی‌ها — Marketplace Freelance

> نسخه ۰.۱ — تمرین ۱ درس آزمایشگاه نرم‌افزار

## ۱. هدف سیستم

پلتفرمی وب‌محور که کارفرمایان (Clients) پروژه‌های خود را ثبت می‌کنند، فریلنسرها (Freelancers) پروژه‌ها را جست‌وجو و پیشنهاد (Proposal) ارسال می‌کنند و کارفرما بهترین پیشنهاد را انتخاب می‌کند.

## ۲. تحلیل سیستم‌های مشابه

> نکته: قبل از تحویل، هر دو سایت را خودتان یک بار مرور کنید و موارد زیر را با آنچه می‌بینید تطبیق دهید.

### ۲.۱ پونیشا (Ponisha) — نمونه ایرانی

| پرسش | تحلیل |
|---|---|
| نقش‌ها | مهمان، کارفرما، فریلنسر، مدیر سیستم |
| ثبت پروژه | کارفرما عنوان، توضیحات، دسته‌بندی، مهارت‌های مورد نیاز، بازه بودجه و مدت انجام را وارد می‌کند؛ پروژه پس از بررسی مدیر منتشر می‌شود |
| پیدا کردن پروژه | لیست پروژه‌ها با فیلتر دسته‌بندی، مهارت و بودجه و جست‌وجوی متنی |
| پیشنهاد | فریلنسر مبلغ، زمان تحویل و توضیحات را ارسال می‌کند؛ کارفرما پیشنهادها را مقایسه می‌کند |
| پس از انتخاب | شروع همکاری، پرداخت امن (واسطه‌ای/امانی)، تحویل کار، تأیید و آزادسازی پول |
| همکاری | پیام‌رسانی داخلی، ارسال فایل، ثبت وضعیت پروژه |
| پروفایل فریلنسر | نام و عکس، بیوگرافی، مهارت‌ها، سوابق کاری و تحصیلی، نمونه‌کار |

### ۲.۲ Upwork — نمونه خارجی

| پرسش | تحلیل |
|---|---|
| نقش‌ها | Visitor، Client، Freelancer، Agency، Admin/Support |
| ثبت پروژه | Job Post شامل عنوان، توضیح، مهارت‌ها، سطح تجربه، نوع قرارداد (ثابت یا ساعتی) و بودجه |
| پیدا کردن پروژه | جست‌وجو و فیلتر، پیشنهاد پروژه‌های مرتبط بر اساس مهارت‌های پروفایل |
| پیشنهاد | Proposal شامل Cover Letter، مبلغ یا نرخ ساعتی و پاسخ به سؤالات کارفرما؛ سیستم اعتبار (Connects) برای ارسال |
| پس از انتخاب | ارسال Offer، پذیرش، ایجاد Contract، Escrow و Milestone |
| همکاری | پیام‌رسانی، تماس، ثبت زمان کار (Time Tracker)، گزارش، ثبت امتیاز و نظر دوطرفه |
| پروفایل | عنوان حرفه‌ای، خلاصه، مهارت‌ها، سوابق کاری و تحصیلی، زبان‌ها، نرخ ساعتی، Portfolio |

### ۲.۳ پروفایل و پورتفولیو

- **اطلاعات پروفایل:** نام، عکس، عنوان شغلی، بیوگرافی، مهارت‌ها، سوابق کاری، تحصیلات، زبان‌ها، نرخ پیشنهادی.
- **نمونه‌کار:** عنوان، توضیح، دسته‌بندی، مهارت‌های به‌کار رفته، تصویر/فایل، لینک پروژه، تاریخ انجام.

### ۲.۴ نقش‌ها و فعالیت‌ها (Actors)

| نقش | فعالیت‌ها |
|---|---|
| مهمان | مشاهده پروژه‌ها و پروفایل‌های عمومی، ثبت‌نام، ورود |
| کارفرما | ثبت/ویرایش/بستن پروژه، بررسی پیشنهادها، انتخاب فریلنسر، تأیید تحویل، امتیازدهی |
| فریلنسر | تکمیل پروفایل، مدیریت نمونه‌کار، جست‌وجوی پروژه، ارسال پیشنهاد، تحویل کار |
| مدیر | تأیید پروژه‌ها، مدیریت کاربران، رسیدگی به گزارش تخلف و اختلاف |

## ۳. نیازمندی‌های عملکردی (Functional)

- **FR-01:** سیستم باید امکان ثبت‌نام کاربر با ایمیل و رمز عبور و انتخاب نقش (کارفرما یا فریلنسر) را فراهم کند.
- **FR-02:** سیستم باید ورود و خروج کاربران را با احراز هویت پشتیبانی کند و دسترسی‌ها را بر اساس نقش محدود کند.
- **FR-03:** فریلنسر باید بتواند پروفایل خود را شامل بیوگرافی، عنوان شغلی، مهارت‌ها، سوابق کاری و تحصیلات تکمیل و ویرایش کند.
- **FR-04:** فریلنسر باید بتواند نمونه‌کار (عنوان، توضیح، مهارت‌ها، تصویر/فایل، لینک) اضافه، ویرایش و حذف کند.
- **FR-05:** سیستم باید به کارفرما اجازه دهد پروژه جدیدی شامل عنوان، توضیحات، دسته‌بندی، مهارت‌های لازم، بودجه و مهلت انجام ثبت کند.
- **FR-06:** کارفرما باید بتواند پروژه‌های خود را ویرایش یا ببندد، مادامی که فریلنسری برای آن انتخاب نشده است.
- **FR-07:** سیستم باید لیست پروژه‌های باز را به‌صورت صفحه‌بندی‌شده نمایش دهد.
- **FR-08:** سیستم باید جست‌وجوی متنی و فیلتر پروژه‌ها بر اساس دسته‌بندی، مهارت و بازه بودجه را ارائه دهد.
- **FR-09:** فریلنسر باید بتواند برای هر پروژه باز فقط یک پیشنهاد شامل مبلغ، مدت تحویل و توضیحات ارسال کند.
- **FR-10:** کارفرما باید بتواند پیشنهادهای دریافتی هر پروژه را ببیند، پروفایل پیشنهاددهنده را بررسی و آن‌ها را مرتب کند.
- **FR-11:** کارفرما باید بتواند یک پیشنهاد را بپذیرد؛ در این صورت وضعیت پروژه به «در حال انجام» تغییر کند و سایر پیشنهادها رد شوند.
- **FR-12:** سیستم باید به فریلنسر و کارفرما اعلان (Notification) درباره ثبت پیشنهاد، پذیرش یا رد آن نمایش دهد.
- **FR-13:** فریلنسر باید بتواند کار انجام‌شده را تحویل دهد و کارفرما بتواند آن را تأیید یا درخواست اصلاح کند.
- **FR-14:** پس از اتمام پروژه، هر دو طرف باید بتوانند به یکدیگر امتیاز و نظر ثبت کنند.
- **FR-15:** مدیر سیستم باید بتواند پروژه‌ها و کاربران را مشاهده، مسدود یا حذف کند.
- **FR-16:** دو طرف قرارداد باید بتوانند در چارچوب یک پروژه پیام متنی رد و بدل کنند.

## ۴. نیازمندی‌های غیرعملکردی (Non-Functional)

- **NFR-01 (امنیت):** رمز عبور کاربران باید با الگوریتم مناسب (مانند bcrypt یا Argon2) به‌صورت Hash ذخیره شود و هرگز به‌صورت متن ساده نگهداری نشود.
- **NFR-02 (امنیت):** تمام ارتباطات کلاینت و سرور باید روی HTTPS انجام شود و ورودی‌ها در برابر SQL Injection و XSS اعتبارسنجی شوند.
- **NFR-03 (کارایی):** در شرایط عادی، زمان پاسخ‌گویی صفحات لیست و جست‌وجو برای ۹۵٪ درخواست‌ها باید کمتر از ۲ ثانیه باشد.
- **NFR-04 (دسترس‌پذیری):** سیستم باید حداقل ۹۹٪ از زمان در دسترس باشد (به‌جز زمان‌های اعلام‌شده نگهداری).
- **NFR-05 (قابلیت استفاده):** رابط کاربری باید فارسی و راست‌به‌چپ، و روی موبایل و دسکتاپ (Responsive) قابل استفاده باشد.
- **NFR-06 (نگهداشت‌پذیری):** کد باید در Git نسخه‌بندی شود، ساختار لایه‌ای داشته باشد و تغییرات از طریق Pull Request و بازبینی وارد شاخه اصلی شوند.
- **NFR-07 (یکپارچگی داده):** حذف یا تغییر داده‌ها نباید باعث ناسازگاری (مثلاً پیشنهاد بدون پروژه) شود؛ بر پایه قیدهای کلید خارجی دیتابیس تضمین شود.
- **NFR-08 (حریم خصوصی):** اطلاعات تماس کاربران تنها پس از شروع همکاری برای طرف مقابل نمایش داده شود.

## ۵. نسخه اولیه (MVP) و نسخه‌های بعدی

### MVP

- ثبت‌نام، ورود و نقش‌ها (FR-01، FR-02)
- پروفایل فریلنسر و نمونه‌کار (FR-03، FR-04)
- ثبت و مدیریت پروژه (FR-05، FR-06)
- لیست، جست‌وجو و فیلتر پروژه‌ها (FR-07، FR-08)
- ارسال، بررسی و پذیرش پیشنهاد (FR-09 تا FR-11)
- پنل ساده مدیر (FR-15)

### نسخه‌های بعد

- اعلان‌ها (FR-12)، تحویل کار و تأیید (FR-13)
- امتیازدهی و نظرات (FR-14)، پیام‌رسانی داخلی (FR-16)
- پرداخت امن (Escrow) و Milestone
- پیشنهاد خودکار پروژه بر اساس مهارت‌ها
- ثبت زمان کار برای قراردادهای ساعتی، اپلیکیشن موبایل، سیستم اختلاف

## ۶. ابهامات و سؤال از کارفرما

1. **پرداخت:** آیا سیستم باید پرداخت و کیف پول داشته باشد (درگاه پرداخت، کمیسیون سایت) یا فقط مرحله انتخاب فریلنسر در محدوده پروژه است؟
2. **تأیید پروژه:** آیا پروژه‌ها قبل از انتشار باید توسط مدیر تأیید شوند یا بلافاصله منتشر شوند؟
3. **نقش کاربر:** آیا یک کاربر می‌تواند هم‌زمان هم کارفرما و هم فریلنسر باشد، یا هر حساب فقط یک نقش دارد؟
4. **پیشنهاد:** آیا محدودیتی برای تعداد پیشنهاد فریلنسر یا امکان ویرایش/پس‌گرفتن پیشنهاد وجود دارد؟
